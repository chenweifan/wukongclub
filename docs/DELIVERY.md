**「终止开发」的含义**：这些路由**保留可达**，页面明确标注「未交付」并说明原计划内容，
同时给出已交付模块的入口。这样做的代价很小（几行占位组件），收益是评审不会把
「没做」误判成「坏了」。

## 3. 验收步骤

```bash
npm install
npm run verify     # 格式校验 → 类型 → Lint → 单测 → 构建 → 产物冒烟
npm run dev        # 人工走查：http://127.0.0.1:5173
```

`npm run verify` 的每一步都可以单独跑：

| 命令                   | 覆盖什么                                                                                                |
| ---------------------- | ------------------------------------------------------------------------------------------------------- |
| `npm run format:check` | Prettier（源码、Storybook 配置、根级配置与 Markdown、脚本）                                             |
| `npm run typecheck`    | `tsc --noEmit`，strict + `noUncheckedIndexedAccess`                                                     |
| `npm run lint`         | ESLint，`--max-warnings 0`                                                                              |
| `npm test`             | Vitest：纯函数、契约守卫、Repository + MSW + Dexie 集成、路由级集成、组件交互                           |
| `npm run build`        | 类型检查 + 生产构建（含懒加载分包）                                                                     |
| `npm run smoke`        | 用 `vite preview` 伺服 `dist/`，逐个请求路由与 `mockServiceWorker.js`，断言 200 + 挂载点 + 真实产物引用 |

`npm run smoke` 覆盖的路由：`/`、`/news`、`/wiki`、`/guide`、`/user`、`/login`（已交付）
以及 `/forum`、`/admin`（未交付/守卫）与一个不存在的路径（404 页由 SPA 承接）。
它验的是「产物能不能被真实伺服并挂载」，这是 jsdom 单测覆盖不到的一层。

## 4. 收尾做了什么（阶段 4）

1. **诚实化降级**：导航、首页、占位页、场景、引导统一读「交付状态」这一份数据
   （`src/app/navigation.ts` 的 `status: 'delivered' | 'planned'`），
   未交付模块一律带「未交付」标记；测试守住这条不变量。
2. **修掉被终止模块拖坏的运行时行为**：
   - 首次到访引导的跨页步骤原本指向已被真实页面取代的占位页锚点（会「跳过去但高亮不到东西」），
     现改为影神图列表区锚点，并加了路由级测试确保该锚点真实存在；
   - 三个预设场景原本落在空白占位页上，现改为落在已交付页面
     （满量数据 → 影神图；版主身份 → 后台 403 演示；赛季 → 资讯时间线）；
   - `/user/:userId` 原本会渲染**当前登录用户**的档案，现改为明确的未交付说明页。
3. **验收脚本**：新增 `npm run verify`（一条命令跑完全部门禁）与 `npm run smoke`
   （零依赖的产物冒烟，含端口探测、超时与退出码）。
4. **文档**：本文件 + README 的「交付状态 / 进度 / 技术栈实际引入情况」更新。

## 5. 已知限制与债务

- **没有浏览器级 E2E**：引导（driver.js）、拖拽、虚拟滚动的真实滚动手感只能人工验证。
  手工路径见第 6 节。
- **演示数据是「演示数据」**：资讯中的 `official` / `media` 是聚合占位（正文明确标注），
  攻略数值与时机未校验；页面均常驻说明。
- **快照与场景的分工**：场景链接携带的是**状态**（身份/界面态/主题/seed/tour），
  `seedData` 是一次性写库动作，不会因打开链接而重放；需要连数据一起复现时用快照导入导出。
- **首页探针面板保留**：它是演示系统的常驻自检面（真实走 Repository → MSW → IndexedDB），
  不是业务列表；业务数据在各模块自己的页面上。
- **性能**：主包约 466 kB（gzip ≈ 155 kB）；`demoData`（含 faker）与 ECharts 图谱各自懒加载，
  因此构建会有「chunk > 500 kB」提示 —— 这两块都不进首屏，属于有意为之。
- **无障碍**：已覆盖跳转链接、遮罩 `aria-hidden`、`aria-pressed`/`aria-live`、
  有序列表步骤语义；尚无自动化 axe 门禁。

## 7. 交接要点（如果要继续开发）

- 新增业务模块的标准动作：`data/contracts` → `data/db`（Dexie 版本 +1）→ `data/seeds` →
  `data/mocks/handlers` → `data/repositories` → `entities/*/queries` → `features/*` →
  `pages/*` → story + 测试 → README 章节。
- 交付状态：`src/app/navigation.ts` 里把对应项从 `planned` 改成 `delivered`，
  首页、导航、占位页与测试会自动跟随；场景路由的白名单在
  `src/demo/scenarios/scenarios.test.ts`（目前只允许 `/admin` 作为「刻意演示守卫」的例外）。
- 未交付路由：保留 `PagePlaceholder`，不要删路由 —— 删掉会让外部链接变成 404。
